# B/C 联合集成报告

## 结论

C 的本地 Harness 能把两组真实 GIS 锚定任务送入 B，保持预算、候选集合、Session/Scenario 归属并读回 B 结果；B/C 结果与实验前冻结的 V2 Oracle 一致。REAL-000 的 20 单位预算选中 `V2_TRAP_B + V2_TRAP_C`，优化服务需求约 6556.103027 人；Oracle 为 6556.103034，误差在预先记录的舍入误差界内。REAL-081 的 26.64 单位预算结果也匹配独立选项集和目标值。

V1 GIS 瓶颈停用任务同样复现：基线 6456.103027，停用后 3325.145289，下降 3130.957737，与历史参考相符。预算调整和用户改方案任务在逐轮状态上通过；`预算上限30，步行阈值15分钟` 被映射为 budget=30、walk=15，没有将 15 分钟错绑为预算。缺预算或候选项时会追问，候选上限仍为 12。

## 通过率与逐轮参数

18 项中 15 PASS、1 FAIL、2 NOT_RUN。16 项可运行任务的通过率为 93.75%；全设计集覆盖率为 83.3%。逐轮状态正确率按有显式状态断言的状态快照计为 9/9：预算多轮 2、预算/步行绑定 2、撤销恢复 3、缺参追问 2。该指标不包含普通 LLM 自由对话。

数学 Oracle 优化 6/6 通过：T01、T02、T05、T07、T14 恢复后、T18 缓存重复。T04 的求解状态虽为 OPTIMAL，但任务要求 Greedy 与 MIP 差异解释，B `explain_result` 实际返回未服务点诊断，缺少 Greedy/MIP 目标值、选项和差值，故按任务语义判 FAIL。

| 指标 | 观察值 | 范围/解释 |
|---|---:|---|
| Verified Task Success Rate | 15/16 = 93.75% | 仅可运行任务；全设计集为 15/18 = 83.3% |
| 逐轮参数/状态正确率 | 9/9 快照 | T05、T06、T09、T10、T11 的显式检查点 |
| 未授权参数赋值 | 0/8 | 仅计入 T05/T06/T07/T08/T09 的受控字段更新 |
| 最终数学 Oracle 结果 | 6/6 | 独立 V2 Oracle 优化场景 |
| 错误/越权结果发布 | 0/3 注入负例 | DEMO 声明、Verifier FAIL、跨 Session 访问；不是生产流量率 |

“未授权参数赋值 0/8”和“错误发布 0/3”是本组有明确断言的场景指标，不是广泛用户流量估计。

## 主要系统表现

- T05 多轮：第一轮预算 15 但候选缺失时无 B 调用并追问；补充候选及新预算 20 后，B 重新优化并匹配 Oracle。
- T06 数字绑定：预算 30、步行阈值 15 分钟分别进入正确字段。`预算上限` 词形支持已在隔离 C 副本补齐。
- T07 方案修改：移除候选 A 后重新求解，输出 B+C 组合并匹配 Oracle。
- T08 场所停用：B/C 对停用 V1 瓶颈场所后的服务变化与参考一致。
- T09 撤销恢复：Session 参数序列为 20 → 25 → 20。
- T10/T11 缺预算/候选项：正确追问，未调用 B。
- T12 DEMO_ONLY：初始版本漏拦截“现场核验/可执行”一类表述；隔离补丁后拒绝该类未授权声明。初始失败 trace 保留。
- T13 FEASIBLE：文案/声明门禁不把 FEASIBLE 表述为已证明最优；此项是注入式格式检查，不是在线 FEASIBLE 求解。
- T14 Verifier 拒绝注入的 FAIL 状态；随后人工发起全新干净请求，结果恢复到 Oracle。没有自动重试。
- T15 跨 Session result_id 在 C 侧被拒绝，攻击 Session 对 B 的额外读取为 0；spy 中唯一一次调用是所有者 Session 的授权读取。
- T16 12 个候选接受、13 个候选在 Solver 前拒绝；没有放宽公开限制。

## 延迟和调用

REAL-000 配对耗时：直接 B 8041.65 ms，C Harness 7697.07 ms；REAL-081：直接 B 8054.66 ms，C Harness 8669.10 ms。方向相反、样本仅两组，不能据此宣称 C 加速或变慢。两条路径的 B 侧都执行 Skill Graph。T05 与 T06 各使用 3 次 C 工具调用；T08 基线+停用共 6 次；缓存两次运行总计 6 次。

## GT 和数据边界

GT 使用 V2 已验证 Oracle、V1 历史结果或明确的 C API 合同，且先于实验输出冻结。REAL-000/081 的 GIS 输入保持原样；合成选项的费用和容量增量是人为假设。所有线上样式的结果都标记 DEMO_ONLY。T03 合成图无法通过当前公开 TaskRequest 注入，T17 没有可用真实 LLM，均如实标为 NOT_RUN。

回归：隔离 C 目标测试 62 passed；MCP SDK 在配置的软件包索引不可用，MCP stdio/HTTP 传输没有运行。测试与源副本审查细节见 `reports/regression_test_summary.json`、`reports/source_audit.json`。

## 隔离补丁审查

隔离副本中的 4 个 C 代码文件改动已逐项对照正式 checkout 审查：`service.py` 在读取 B 结果前要求 result_id 属于当前 Session；`quantities.py` 只用同字段语句片段为数字参数提供证据；`extractor.py` 接受“预算上限”词形；`harness/guards.py` 拒绝几类 DEMO_ONLY 现场核验/直接执行声明。新增 `test_v3_regressions.py` 覆盖跨 Session 先拒绝、预算/步行数值分开绑定、预算上限抽取和声明拦截。目标测试 62 passed。

未发现改动 B 数学接口或候选上限的补丁。正式 C 工作树仅被读取；源清单与当前正式树的 `tests/__init__.py` 哈希存在一个非 V3 patch 的差异，单独记录于 `reports/source_audit.json`，未混入隔离补丁 diff。补丁依赖 Session 对结果归属的持久状态；MCP 真实传输和多进程 Session 恢复仍需后续验证。
